# User-needs validation plan
- Date: 2026-10-28  - Author: Claude Code (draft)  - Status: draft, not run

## Hypotheses to test
1. Target users can name a specific need (not just "a better job") when prompted with a goal.
2. They would accept help from a stranger if the request is consent-based and reciprocal.
3. They are willing to offer something in return.
4. A single concrete next step is enough to start a useful collaboration.

## Method (fits the hackathon window)
- 5 to 8 short conversations (15 minutes) with people in the target group the team already knows,
  or posts in communities whose rules allow it.
- Show the onboarding prompt and a mock candidate card; ask what they would do and what worries them.
- Record answers as anonymised notes in `research/findings/` (no names, no contact details,
  consent to take notes asked first).

## What would change the plan
- If most people cannot name a specific need, invest in the goal → need extraction step.
- If people refuse stranger introductions even with consent, emphasise existing-community use.
